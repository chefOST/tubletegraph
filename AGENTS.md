# Project guidance

- At the start of every conversation, read README.md, then the relevant linked context, documentation and paper notes.
- Be as concise as possible when editing or writing documentation. Use short sections and minimal formatting; link to canonical context instead of duplicating it.
- Distinguish published results, ChefOST experiments and proposals. Follow the README's metric definitions; ask about unresolved choices rather than inventing defaults.
- Newer user instructions and supplied announcements take precedence over older notes.
